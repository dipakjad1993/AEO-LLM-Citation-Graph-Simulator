What this does: How many hidden web-search queries the LLM may generate per buyer question. Tip: leave at 3 — more queries = more sources captured but higher API cost.
What this does: Which index the retrieval layer should favor. Note: ChatGPT uses Bing internally; Perplexity and Gemini mix multiple indexes. Auto is safest.

3 · Temporal Grounding & Model Freshness Indexing

Ground Answers to a Content-Freshness Timestamp New

LLM responses drift across model update cycles and index re-crawls. Pin a freshness timestamp and run identical prompts against historical model snapshots to isolate whether a SoMV shift came from your site or the model re-indexing.

Enable Temporal Grounding
Attach a content-freshness reference point to every query
Where to find: Today's date or your last site-wide content refresh date. Tool: check your CMS "last modified" report (WordPress: WP last updated column, or run a sitemap crawl with Screaming Frog and sort by lastmod).
Where to find: The exact model + snapshot ID. Tools: OpenAI model docs (platform.openai.com/docs/models), Anthropic release notes, Google Gemini version history, LMSYS Chatbot Arena leaderboard for naming. Format: model-snapshotdate.
Where to find: The current live snapshot of the same model. Tool: same docs as above — compare old vs new snapshot to isolate "model re-index drift" from "your site change".
What this does: Paired A/B runs the same buyer prompt against both snapshots so you can attribute a SoMV delta to the model's re-index instead of your content. Tip: use Paired A/B for the 20 highest-value prompts.
4 · Geographic Proxy & Localization Injection

Simulate Real Enterprise Buyer Locations New

A CISO in London gets different citations than one in Austin. Rotate residential proxies across hyper-specific enterprise markets so retrieval results match the buyer's actual geography.

Enable Geographic Localization
Route queries through market-specific proxy points
Where to find: Pick the markets where you actually sell to enterprise buyers. Tools: pull from your CRM (Salesforce/HubSpot) "account by region" report, or GA4 (Admin → Audience → Location) to see where high-value sessions originate.
What this does: Residential/ISP proxies look like real consumers (datacenter IPs get filtered by Google/bot-detection). Providers: Bright Data, Oxylabs, Smartproxy, IPRoyal. Residential is required for realistic geo-localized retrieval.
Where to find: From your proxy dashboard's "Proxy Access" page. Format: host:port. Example: Bright Data shows brd.superproxy.io:22225. Leave the port so the orchestrator can rotate IPs.
What this does: How often to request a new IP from the proxy pool. Tip: 5 min for normal runs; use 1-2 min for large batches to avoid rate limits. Rotating per-market gives each market a clean IP.
Where to find: Username from your proxy dashboard — often includes country/region session params, e.g. lum-customer-ACME-zone-resi-country-us. Provider: Bright Data / Oxylabs / Smartproxy dashboards.
Security note: Stored only in your local data/system_inputs.json (never sent to any third party). Tool: your proxy provider's password/key.
5 · LLM Providers & Execution

Execution Parameters

Model selection happens via API keys in .env. Control concurrency, budget, and query volume here.

What this does: How many buyer queries to run per model. Tip: 50 is statistically meaningful for SoMV; use 200+ for enterprise-level confidence (95% CI ±4%). Cost scales linearly.
What this does: Parallel API calls. Tip: 10 is safe for most providers. Check your provider rate limits (OpenAI: platform.openai.com/usage; Anthropic: console.anthropic.com). Too high = 429 errors.
What this does: Sampling randomness. Tip: keep ≤0.2 for deterministic enterprise retrieval; raise to 0.7 only for persona-creativity prompts. Lower = more reproducible SoMV.
Enable RAG / Web-Search Mode
Dual-query attribution runs prompts with web search ON and OFF to split RAG vs base-weight influence
What this does: "ON" = the LLM searches the live web (captures real citations); "OFF" = base training-weight answer (captures pre-search brand memory). Running both lets the tool separate retrieval-sourced vs memory-sourced brand mentions. Tip: leave ON for the full analysis.

Entity Map & Knowledge Base

Where to find: A JSON map of your brand + alias URIs and competitor matrix. Tool: generate from a Google Knowledge Graph search (knowledgegraphsearch.com) or use Schema.org entity types on your site. Defaults auto-build from your Brand field.
Ground-Truth Corpus
Docs, authority URLs, gold-standard set (JSON/TXT/MD)
Where to find: Your own docs site, whitepapers, and the authority sources you WANT to be cited from. Tools: export your docs (WordPress/Notion/Hugo), plus competitor-citing sources found via Backlinko / Ahrefs "referring domains". Used for verification + missing-node detection.
System Config
Model routing, rate limits, decoding overrides (JSON/YAML)
Where to find: Copy from config/execution.json + config/models.json in the project repo. Tip: edit these to override which models get called and rate limits per provider. Defaults are loaded automatically if you skip this.
Existing Simulation Results
Previously exported all_results.json (skip to analysis)
Where to find: Any previous run's all_results.json (saved under data/results/<run-id>/). Uploading this lets you re-analyze a past simulation without re-spending API budget. Tip: great for re-running enterprise analytics after model updates.
